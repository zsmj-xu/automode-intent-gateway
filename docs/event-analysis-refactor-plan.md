# AutoMode 统一事件入口、分析引擎与管理端改造

日期：2026-09-09

状态：本轮代码审查修复完成，本地回归通过（后端 204 项、前端 9 项及生产构建）。完整计划的生产容量等验收不在本轮覆盖范围内。

架构与安全评审已完成。告警等级、孤儿响应生命周期、分阶段调度及代理旁路落盘要求已合入正文；本文描述目标设计，当前实现与已验证范围见 [代码审查修复记录](event-refactor-review-fixes.md)。

## 1. 目标与范围

将 AutoMode 从“代理内置分析”改为“标准事件接入 → 独立分析引擎 → 管理端”。首期采用单实例、内部模块解耦，先跑通可靠接收、双通道分析和告警闭环。

- 外部服务负责连接数据库、日志平台或网关，并转换为标准事件；本期不实现 LiteLLM、Higress 或数据库连接器。
- 原代理保留为可选适配器，复用同一个分析引擎。
- 请求是 DLP 主判定对象；响应用于调用结果和工具调用旁证，不新增响应 DLP。
- 实时与历史事件均支持 LLM 分析；历史事件不回填会话意图风险。
- 会话意图风险继续作为独立告警类型，保留现有实时分析语义。
- 本期不实现阻断、路由和在线脱敏，不承诺单实例已能承载每天 110 亿 token。

## 2. 标准事件入口与可靠接收

### 接口和事件契约

- 新增 `POST /v1/events`，首期单次提交一个事件；提供 JSON Schema、合成样例及调用示例。现有 `/api/events` 继续用于管理端 SSE。
- 支持三类事件：请求、响应、完整调用记录。流式响应由接入服务汇总后提交，可携带完整或截断的 SSE 文本；首期不提供逐 chunk 上传协议。
- 必要字段包括版本、事件 ID、来源 ID、调用 ID、发生时间、实时/历史标记、协议、采集阶段和内容完整性；正文、身份、模型目标、会话 ID、调用尝试 ID 按事件类型提供。
- 区分入口请求、模型出站请求和未知采集阶段；内容区分完整、截断、已脱敏及缺失。支持现有三种模型协议。
- 模型目标按事件解析，信任等级由服务端目标注册表决定；缺失目标保持未知、按 external 策略评估，不声称已证明外发。

### 关联与幂等

- 按来源、调用、尝试及采集阶段关联请求和响应，支持响应先到。尚无请求时只保存旁证，不能产生“请求安全”结论。
- 响应处理不等待请求：提取并提交脱敏工具调用及调用结果旁证后，响应任务即标记为 `completed`，释放该响应的临时加密正文；没有请求时，调用关联状态独立标记为 `request_missing`。处理状态与关联状态分开保存，不占用 worker 或以 pending 任务等待配对。
- 在元数据保留期内，迟到请求仍按关联键补齐，并独立触发请求分析，不重复生成已有响应旁证。超过保留期仍无请求的记录按清理策略回收；不设置 15～30 秒的短时关联失效窗口，以支持历史日志乱序及延迟补发。
- 以来源和事件 ID 幂等；重复相同内容返回已有接收结果，不重复分析或告警；同 ID 不同内容返回冲突。
- 请求和完整记录重叠时，对已有请求部分校验一致性，仅补齐响应；冲突不覆盖。跨来源记录不自动合并。
- 新增来源授权配置：每个来源使用独立接入 token，并配置是否允许提供可信身份；请求中的 `trusted` 字段不能自行取得信任。接入凭证与管理凭证分离。

### 接收可靠性

- 返回 `202` 前完成加密正文落盘和任务索引提交；返回接收 ID 及查询地址。新增 `GET /v1/events/{event_id}`，仅允许来源读取自己的状态。
- 正文存放于独立加密磁盘缓冲，SQLite 保存任务索引与管理数据。使用原子文件写入、持久化同步和启动恢复处理文件与数据库之间的中断。
- 默认单事件上限 32 MiB、加密磁盘缓冲上限 1 GiB，均可配置。容量不足返回可重试错误，绝不先确认再静默丢弃。
- 规则处理与 LLM 复核使用独立的持久化阶段任务和并发限制：`AUTOMODE_RULE_CONCURRENCY` 默认 2，`AUTOMODE_REVIEWER_CONCURRENCY` 默认 5。worker 按空闲槽领取任务，不把磁盘积压全部载入内存；处理规则与阻塞式 LLM 调用使用隔离的执行资源，均不得阻塞 HTTP 事件循环。
- 规则阶段先提交规则结果和即时告警，再将候选事件交给 LLM 队列，随后释放规则工作槽。没有后续分析任务的事件直接完成并归档；慢速 LLM 不占用规则并发槽。实时会话意图 reviewer 同样受 LLM 并发限制，不能绕过限额创建无限后台调用。
- 分阶段保存执行状态，重启或 LLM 重试不重复提交已完成的规则结果。LLM 排队期间保留后续分析所需的加密正文，整体仍受磁盘容量限制；队列隔离不等于消除积压，缓冲满时按接收背压处理。
- 上述并发数是首期可配置默认值，不代表吞吐保证；规则耗时、LLM 延迟与实际吞吐以本项目压测为准。
- 任务支持 pending、processing、completed、failed。基础处理异常自动重试三次，随后保留失败任务和加密正文，允许管理员重试；未完成正文不因定时清理被删除。
- 新标准入口必须配置加密密钥。结果提交后再删除临时正文；崩溃恢复不得重复创建告警或累计会话计数。LLM 调用可能因崩溃重试，结果落库必须幂等。

## 3. 独立分析引擎与双通道告警

从 `Gateway` 中抽出协议整理、会话关联、DLP、LLM 调度、响应旁证和结果存储编排。入口与代理只负责采集和提交，引擎不依赖全局 upstream。

### 双通道分别记录结论

| 规则通道 | LLM 通道 | 聚合结果 |
|---|---|---|
| 高危／严重 | 任意结果，包括失败、未完成或无告警 | 至少保留规则等级；若 LLM 有更高告警等级则采用更高等级 |
| 中危 | 确认告警 | 至少升为高危；若 LLM 判为严重则采用严重 |
| 中危 | 明确无告警 | 中危，标记结论分歧 |
| 中危 | 跳过、未完成、失败或无法判断 | 中危，分别标记跳过、待复核或分析失败 |
| 无告警 | 告警 | 采用 LLM 判定等级 |
| 无告警 | 无告警或无需分析 | 不产生 DLP 告警 |
| 无告警 | 未完成、分析失败或无法判断 | 待复核，不能展示为安全 |

风险严重性、命中来源与复核状态分别记录；规则告警不因 LLM 缺席或反对而降低等级。即使 LLM 判断为误报，也保留规则等级和分歧依据，由人工处置或后续修正规则解决。双命中可以提升等级，但不是高危的必要条件。

- 规则检测和策略匹配继续保留；凭据、PII 等确定性命中不会被 LLM 删除或降级。分别保存规则原始等级、LLM 判定等级、聚合等级和复核状态，保留 `low`、`medium`、`high`、`critical` 风险枚举；无告警不等于未完成分析。
- 有检测线索或策略要求 `review` 时调用 LLM，即使规则通道未告警；没有候选线索则跳过。现有受控元数据匹配仍记录其处置依据。
- LLM 接收脱敏上下文、角色、JSON 路径、检测位置、目标及必要身份信息。遮盖凭据和 PII，源码内容沿用现有脱敏边界；上下文不足可返回无法判断。
- 复用现有 Fast/Deep 配置：Fast 给出有效结论时使用，否则进入 Deep；均失败时保留独立失败状态，不伪造成 LLM 告警或无风险。
- 实时和历史使用相同候选触发与 DLP 复核流程。历史记录保存原发生时间、实际分析时间及分析版本；不按历史策略模拟当时结论。
- 一次请求观察只生成一条聚合 DLP 告警。规则先命中时按其原始等级立即告警，不等待 LLM；LLM 后续完成时按矩阵更新等级和复核状态，保持告警 ID 和人工处置记录稳定。
- 双命中升级必须来自同一次请求观察的两方结论，不能跨事件拼接；单通道本身可以产生高危或严重告警。历史既有告警不自动重算。
- 不完整数据仍可产生有依据的告警，但无命中不能等同完整检查通过。处理完成状态与内容完整性独立展示。

## 4. 存储、兼容与管理端

### 保留策略

- 普通事件完成后，仅保存来源、时间、模型、状态、完整性、分析摘要、检测结果及脱敏工具调用旁证；不长期保存请求或响应正文。
- 产生 DLP 告警时，另存加密请求证据，沿用 30 天留存和原文访问审计。已有证据读取接口兼容原数据库记录与新文件证据。
- 新事件摘要、幂等记录和分析记录默认保留 30 天，清理时保持引用一致；明确幂等保证窗口为 30 天。
- 保留必要的不可逆会话指纹，并按来源隔离会话标识。实时与历史会话分组隔离，避免历史乱序影响当前意图状态。
- 普通调用正文删除后，回放入口明确显示“正文未保留”；需要重新分析时由接入服务重新提交，不能拿摘要冒充原请求。

### 运行与兼容

- `serve` 不再强制要求 upstream；未配置时只启动事件接收、分析和管理端，配置后启用原代理。
- 原代理复用标准事件模型和引擎，但采用非阻塞旁路投递：转发前不得等待加密、磁盘写入或分析结果；有密钥时由独立后台持久化 worker 写入可靠缓冲，再交给分析引擎。标准事件入口 `POST /v1/events` 则必须等待持久化完成才返回 `202`。
- 代理旁路内存缓冲按事件数和正文总字节数双重限额，默认 100 个事件、64 MiB，均可配置，包含已领取但尚未完成落盘的事件。入队必须立即成功或拒绝，不得通过无限等待任务绕过限额；满载或落盘失败时继续代理转发，记录按原因区分的审计丢弃／失败计数，日志不携带原文。
- 代理事件成功持久化之前存在进程崩溃丢失窗口；模型转发成功不代表审计事件已可靠接收。成功落盘后才具备重启恢复保证。旧配置未配置密钥时保留有界的尽力分析模式，不提供持久化保证，管理端明确展示该模式。
- 加密与磁盘 I/O 不在 HTTP 事件循环中执行，持久化 worker 不与慢速 LLM 共用执行槽。优雅退出时停止接收新的代理审计事件，最多等待 30 秒排空旁路缓冲；已落盘的分析任务留待恢复，未落盘且未排空的事件记录数量并明确报告。
- 分别测量转发前处理时间 `pre_upstream_ms` 与真实首字节时间 TTFB；前者不能等同于 TTFB 开销，不把未经本项目验证的毫秒数写作性能承诺。
- 代理的审计失败不阻断模型转发，必须暴露失败计数；标准接入 API 则在可靠接收失败时返回错误。
- 保留现有管理 API、旧分类接口和 CLI 兼容性。Playground 使用显式目标上下文，不再依赖代理对象。
- 数据库采用增量迁移，旧记录标记为 legacy；不自动删除、回放或重算现有数据库内容。

### 管理端

- 新增“事件”页面：展示来源、发生/接收时间、采集阶段、完整性、处理状态、双通道结果和关联告警。
- 支持来源、实时/历史、处理状态筛选，提供失败详情及管理员重试。
- 告警页支持规则命中、LLM 命中、仅规则、仅 LLM、双命中筛选；前两项均包含双命中记录。
- 告警页另支持待复核、分析失败和结论分歧筛选；来源标签与复核状态独立，不能把“仅规则”视为 LLM 明确无告警。
- 告警详情并列展示规则依据及原始等级、LLM 结论及等级、汇总等级，明确区分跳过、待分析、失败、无法判断和明确无告警。
- 总览分别展示规则与 LLM 阶段的积压、最老任务等待时间和失败数量，以及磁盘／代理内存缓冲用量、代理审计丢弃计数和可靠性模式。事件页展示 `request_missing` 关联状态。会话意图告警保留独立类型筛选。
- 同步 README、AGENTS.md 和验收文档中的产品定位、启动方式及双通道规则。

## 5. 实施顺序与验收

按“契约与引擎解耦 → 可靠接收与迁移 → 双通道判定 → 管理端 → 集成验证”推进。

必测场景：

- 三种协议，请求/响应分开提交、完整记录、响应先到及历史事件。
- 仅响应事件处理完成后释放正文且不占用 worker；保留期内迟到请求能关联并触发分析，跨重启不重复响应旁证；永久缺失请求的元数据到期可回收，不产生请求安全结论。
- 重复投递、内容冲突、来源隔离、调用重试、多采集阶段及不完整正文。
- 未授权接入、伪造可信身份、缺失目标；凭据不进入明文日志、任务记录或 LLM 上下文。
- 两通道全部组合：规则高危／严重在 LLM 排队、超时、网络失败、跳过和明确无告警时均不降级；规则中危被 LLM 确认后升为至少高危；仅 LLM 告警采用其等级；无规则告警但 LLM 未完成时不得显示安全。
- 来源、待复核、分析失败和分歧筛选准确；异步更新及重试保持告警 ID 和人工处置记录稳定，不重复告警。
- 接收落盘、任务执行、结果提交前后的进程中断恢复；缓冲满、磁盘写入失败和人工重试。
- 用延迟或阻塞的模拟 reviewer 占满 LLM 并发槽，验证规则阶段仍可处理新事件并即时生成告警；各阶段不超过配置并发，积压不导致无界内存增长，重启及复核重试不重复规则结果。
- 普通正文删除、告警证据解密与过期清理、旧数据库迁移、无正文回放提示。
- 无 upstream 的独立服务闭环，以及旧代理 JSON/SSE 透传和会话意图回归。
- 用可控的慢磁盘持久化模拟验证：代理发起上游请求及响应透传不等待审计落盘，而标准事件入口在持久化完成前不返回 `202`；代理缓冲满或落盘失败不影响转发且计数准确，未落盘崩溃窗口与落盘后恢复行为符合约定；优雅退出受排空期限约束。
- 运行完整后端测试、前端测试和生产构建；用合成事件验证持续接收、背压及恢复，记录机器规格和实测结果，不将其表述为生产容量证明。

验收核心：外部服务无需让模型流量经过 AutoMode，即可提交标准事件，经可恢复分析后，在管理端看到来源明确、证据可追溯、可按规则与 LLM 筛选的聚合告警。
