# AutoMode Shadow DLP 控制台说明

## 1. 信息架构

控制台沿用紧凑安全运营风格，当前导航为：

- **总览**：服务健康、DLP 请求、敏感发现、告警率、类别和目标分布。
- **会话**：按工作上下文调查每次出站请求。
- **告警**：状态流转、人工反馈、敏感发现、目标和加密证据。
- **策略**：自然语言 DLP 策略、模型目标注册表和内置/自定义检测器矩阵；旧动作规则折叠为兼容旁证。
- **测试实验室**：离线构造三协议出站请求，不转发目标模型。
- **设置**：Shadow 模式、可选 Fast/Deep、出站 DLP reviewer 提示词、证据密钥和可信网段状态。

## 2. 调查顺序

每个 Trace 首屏固定回答四个问题：

```text
人的用途 → 检测到什么敏感数据 → 发往哪个模型目标 → 策略结论是什么
```

随后才展示：

1. 模型动作旁证。
2. Rules/Fast/Deep 阶段详情。
3. 分类器实际看到的脱敏上下文。
4. 脱敏 Input/Output JSON。

原文不会在会话页出现；只能从告警详情中显式解密。

## 3. 关键交互

- 告警原文默认折叠，解密按钮明确说明仅本机可用且访问会被审计。
- 策略采用“编译预览 → Shadow 测试 → 保存（默认启用）→ 按需启停”的流程。
- 检测器矩阵按类别展示启用状态；自定义正则保存前进行本地样例匹配预检，服务端会再次编译校验。
- 未注册目标空状态明确提示“默认 external”。
- 告警支持 open/acknowledged/false_positive/resolved 和正确/误报/不确定反馈。
- 会话选择、筛选和 Trace 定位保持 URL 状态；Cmd+K 提供导航入口。

## 4. 可访问性与视觉约束

- 风险不能只靠颜色，必须同时显示图标、文本和 reason code。
- 所有表单保留可见 label；异步操作显示 loading、disabled 和就地错误。
- 结构性操作图标统一使用 Lucide；类别标签可附带 emoji，但必须同时包含文字。
- 小屏下策略表单、DLP 摘要和 master-detail 自动改为单列，避免横向滚动。
- 支持可见焦点、Escape 关闭抽屉和 `prefers-reduced-motion`。

## 5. 历史原型

`docs/design-demos/` 下三份 HTML 是旧工具动作审查时期的设计探索，不是当前 UI 规范，也不作为验收依据。是否删除留待工作区清场确认。
