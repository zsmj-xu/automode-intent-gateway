## 修复对应关系

| 审查问题 | 修复与验证 |
|---|---|
| 旧 reviewer 类型错误被伪装为成功 | EventWorker 复用 AnalysisEngine 的 Fast/Deep 通道；超时和未配置保持失败状态，规则高危不降级，保留加密输入供重试 |
| 跨来源同名事件覆盖 | 外部 ID 按来源唯一，内部 UUID 用于文件、索引和任务；两个来源并发提交相同外部 ID 已通过真实 HTTP 测试 |
| 目标、策略和检测器配置未接入 | 统一调用分析引擎加载服务端配置；登记 trusted 目标的实际入口回归通过 |
| 告警缺少原文证据 | 先保存 AES-GCM 证据并关联告警，再按任务状态释放缓冲；超时告警仍可解密证据 |
| 响应工具旁证丢失 | 解包 JSON/SSE 并脱敏持久化工具调用；响应先到及请求迟到关联已验证 |
| 恢复产生重复告警 | 稳定告警 ID、规则与结果提交顺序、分阶段恢复；代理投影使用固定 run ID，保留人工处置状态 |
| 缺失或截断正文被当作安全 | 保存内容完整性和待复核结论；可见敏感内容仍扫描，无命中不等于完整通过 |
| 代理可靠性显示与实际不符 | 共享可靠接入，代理内存按事件数和字节限额；包含 inflight，区分异步代理与标准入口的确认保证 |
| 无 upstream 无法启动 | CLI、应用和 Compose 支持独立服务；加密代理 HTTP 回归同时覆盖原 Trace、响应及工具旁证 |
| 幂等忽略目标等字段 | 规范化哈希包含身份、模型目标、事件类型及关联字段；同 ID 改目标返回 409 |

整合时另外修复了迁移事务内切换 WAL、关闭 worker 后线程仍写库、规则和 LLM 共用执行资源、代理 Trace 长期 pending，以及前端将缺失 LLM 结果默认显示为成功等问题。
